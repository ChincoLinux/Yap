# Pull Request / Solicitación de cambios

> Trabajamos bajo **trunk-based development** ([docs/TRUNK-BASED.md](docs/TRUNK-BASED.md)), con la doctrina organizacional **[A-Dev](ADEV.md)**: ramas cortas, integración frecuente a `main`, PRs atómicas, commits convencionales y evidencia obligatoria.

## Checklist previo (obligatorio) / Prior checklist (required)

- [x] La PR resuelve **un solo objetivo** (atomicidad adev). Si mezcla refactor/feature/docs, dividir.
- [x] Rama corta basada en `main` (trunk-based, idealmente <48h), sin `force push` en la rama.
- [x] El título usa **Conventional Commits**: `feat:`, `fix:`, `docs:`, `refactor:`, `chore:`, `test:`, `ci:`.
- [x] Referencia el issue que resuelve: `Closes #N`.
- [x] Validación ejecutada y evidenciada (check mínima que pruebe el cambio; en Yap: `python3 -m pytest tests/`).
- [x] Sin secretos, credenciales ni datos personales en el diff.
- [x] Contenido comunitario bilingüe cuando aplica (es primario / en mirror).
